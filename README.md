# 삐약푸쉬 / Peep Push

병아리가 알을 밀어 둥지에 넣는 소코반 퍼즐 게임. Flutter로 만들어 Android·iOS를 모두 지원한다
(현재는 Android만 배포, iOS는 코드 호환만 유지).

**총 300스테이지 (20챕터 × 15)** · 13개 언어 · 데일리 퍼즐 · 스티커 수집

| | |
|---|---|
| 패키지 | `com.peep.puzzle` |
| 버전 | `1.0.3+4` — 플레이 스토어 **정식 출시 신청** |
| 앱 이름 | 한국어 **삐약푸쉬**, 그 외 **Peep Push** |
| 스토어 노출명 | 삐약푸쉬 - 소코반퍼즐 / Peep Push - Sokoban Puzzle |

---

## 게임 규칙

- 화면 아래 **조이스틱**(기본) 또는 **십자 방향키**로 병아리를 한 칸씩 이동. 설정에서 선택
- 누르고 있으면 등속으로 연속 이동한다
- 알은 한 번에 하나만, 한 칸씩 **밀 수만** 있다 (당기기 없음)
- 모든 알이 둥지 위에 오면 클리어. 이동수에 따라 별 1~3개
  - 3★ 최적수 이하 · 2★ 최적수 1.5배 이하 · 1★ 클리어
- 되돌리기는 무제한, **힌트는 개수 제한**이 있다
  - 시작할 때 5개, 새 스테이지를 깰 때마다 +1, 오늘의 퍼즐을 깨면 +2
  - 쓰면 병아리가 **몇 번째로 어디에 서야 하는지 번호(1~5)** 로 표시된다
  - 길을 못 찾으면 차감하지 않는다
- 걸을 때마다 쉬익 소리, 벽에 막히면 병아리가 살짝 튕긴다

### 기믹

| 기믹 | 규칙 |
|---|---|
| 얼음 | **알만** 미끄러진다. 비얼음 칸에 들어서거나 막히면 정지. 병아리는 평범하게 걷는다 |
| 굴(텔레포트) | 굴 쌍(1↔2, 3↔4)으로 즉시 이동. 출구가 막혔으면 진입 자체가 불가. 나온 알은 그 자리에 정지 |
| 단추·문 | 같은 색 단추 위에 알이나 병아리가 있는 동안 문이 열린다. 문 칸에 누가 있으면 닫히지 않는다(끼임 방지) |
| 금 간 바닥 | 밟고 떠나면 구멍이 된다. 구멍엔 아무도 못 들어간다. 금 간 바닥 위의 알을 밀면 병아리는 제자리에 남는다 |

### 챕터 구성

한 챕터는 **기본 10판 + 도전 5판(11~15번)** 으로 이뤄진다.

| 막 | 챕터 | 성격 | 기본 10판 | 도전 5판 |
|---|---|---|---|---|
| 1막 · 배우기 | 1–5 | 기믹 하나씩 학습 | 1~36수 | 24~47수 |
| 2막 · 뒤섞기 | 6–10 | 기믹 2종 조합 | 15~25수 | 24~44수 |
| 3막 · 넓어지기 | 11–15 | 넓은 보드, 알 4개 | 22~32수 | 28~48수 |
| 4막 · 시험 | 16–20 | 전 기믹 조합, 알 5개 | 26~41수 | 27~67수 |

- 다음 챕터 해금: 현재 챕터에서 **8스테이지 클리어** (별 개수와 무관)
- 별은 스티커 수집 전용. 누적 25개마다 스티커 1종 해금 (총 24종, 만점 900)
- 데일리 퍼즐: 날짜를 시드로 매일 새 퍼즐 생성(항상 풀이 가능 보장), 달력 도장·연속 출석

## 개발 일지

### 1차 — 게임의 뼈대 (v1)

가장 먼저 정한 원칙은 **게임 규칙을 UI에서 완전히 떼어내는 것**이었다.
`lib/engine/`은 Flutter를 import하지 않는 순수 Dart로 두고, 보드·이동·기믹·데드락 판정을
전부 여기에 넣었다. 덕분에 규칙을 화면 없이 테스트할 수 있었고, 나중에 만든 레벨 생성
도구도 같은 코드를 CLI에서 그대로 돌릴 수 있었다.

기믹은 하나씩 테스트 먼저 쓰고 구현했다. 얼음 미끄러짐, 굴 텔레포트, 단추·문, 금 간 바닥
순서로 붙였는데 상호작용에서 애매한 지점이 계속 나왔다. 예를 들어 *미끄러지던 알이 굴에
들어가면?* → 짝 굴에서 나와 그 자리에 멈춘다. *금 간 바닥 위의 알을 밀면 병아리가
따라 들어가나?* → 알이 떠나는 순간 구멍이 되므로 병아리는 제자리에 남는다.
이런 것들을 테스트로 못박아 두니 나중에 기믹을 조합해도 규칙이 흔들리지 않았다.

**BFS 솔버**를 만든 게 이 프로젝트에서 가장 잘한 결정이었다. 원래는 별 3개 기준(최적
이동수)을 구하려고 만들었는데, 결과적으로 세 가지 일을 한다:

1. 레벨이 **풀 수 있는지** 자동 검증 — 손으로 만든 초기 50개 중 5개가 풀 수 없는
   레벨이었다. 솔버가 없었으면 플레이하다 발견했을 것이다
2. 별 3개 기준값 자동 산출
3. 게임 안의 힌트 기능

레벨 파일은 ASCII 격자 JSON으로 두고(`#`벽 `@`병아리 `$`알 `o`둥지 …), 커밋 전에
`validate_levels.dart`로 전수 검증하는 흐름을 만들었다.

### 2차 — 실기기에서 드러난 것들 (v1.1)

폰에 올려서 해보니 화면으로는 안 보이던 문제가 쏟아졌다.

**이동이 딱딱 끊긴다.** 원인이 세 개 겹쳐 있었다. 이동 애니메이션이 120ms인데 연속 이동
간격이 160ms라 매 칸 40ms씩 멈췄고, 커브가 easeOut이라 칸마다 급브레이크가 걸렸고,
점프 동작이 220ms로 더 길어 엇박이 났다. 셋을 맞춰서 1차로 개선했다.

**챕터 마지막 판에서 다음으로 못 넘어간다.** 코드를 보니 10번째 스테이지의 "다음" 버튼이
그냥 목록으로 돌아가도록 배선돼 있었다. 화면 코드에 묻혀 있어서 놓친 것이라, "다음에 뭘
할지" 판단을 `resolveNextStep()`이라는 순수 함수로 떼어내고 테스트를 붙였다.

**클리어 팝업에 별이 하나도 안 보인다.** 미획득 별까지 등장 애니메이션으로 감싸는 바람에
크기 0인 채로 남아 있었다. 별 개수를 검증하는 회귀 테스트를 추가했다.

이 외에 방향키 확대, 보드 패널·HUD 카드, 잔디 무늬·알 광택 같은 그래픽 디테일을 손봤다.

### 3차 — 200스테이지 확장 (v2)

50스테이지를 다 해보니 너무 쉬웠다. 200개로 늘리되 어렵게 만들기로 했는데,
**150개를 손으로 만드는 건 현실적이지 않았다** (1차에서 50개 만들며 5개가 풀 수 없는
레벨로 나온 걸 생각하면 품질도 보장이 안 된다).

그래서 **생성 + 솔버 필터** 파이프라인을 만들었다:

1. 벽·둥지만으로 "완성 상태"(알이 전부 둥지 위)를 만든다
2. 역방향 이동(걷기·당기기)을 무작위로 적용해 흐트러뜨린다 → 완성 상태로 가는 경로가
   반드시 존재하므로 **풀이 가능성이 보장**된다
3. 기믹 타일을 빈 바닥에 뿌린다 (이 단계에서 막힐 수 있다)
4. 솔버로 재검증하고 난이도를 측정해, 밴드를 통과한 것만 채택한다

난이도를 이동수만으로 재면 안 된다는 걸 중간에 깨달았다. 일직선으로 밀기만 하는 60수짜리는
길 뿐 어렵지 않다. 그래서 솔버가 답을 찾는 김에 네 가지를 함께 잰다:

| 지표 | 무엇을 잡아내는가 |
|---|---|
| 최적 이동수 | 판의 길이 |
| 밀기 횟수 | 걷기만 길고 밀기는 적은 "산책 퍼즐" 배제 |
| 탐색 상태 수 | 같은 이동수라도 갈래가 많으면 눈에 안 보인다 |
| 데드락 비율 | 순서를 틀리면 막히는 함정의 존재 |

4막(알 5개)에서 처음엔 후보가 **하나도** 안 나왔다. 8×8에 알 5개면 남는 칸이 20개
남짓이라 솔버 탐색이 상한을 넘겨 전부 폐기됐던 것. 판을 9×9로 넓히고 벽을 줄여 해결했다.
전체 생성에 1시간 40분이 걸렸다(4막은 챕터당 13~21분).

**진행 잠금의 설계 결함**도 이때 고쳤다. "이전 챕터에서 별 12개"가 조건이었는데, 한 챕터는
10스테이지뿐이라 **전부 클리어해도 별 1개씩이면 10개**여서 영구히 갇힐 수 있었다.
별은 실력 보상이지 관문이 되면 안 된다고 판단해, **클리어 개수 8개** 기준으로 바꿨다.

### 4차 — 조작감과 화풍 (v2.1)

**이동 끊김의 진짜 원인.** v1.1에서 시간은 맞췄는데 여전히 끊겼다. 문제는 **속도 곡선**이었다.
매 칸 easeInOut이면 칸 경계마다 속도가 0으로 떨어졌다가 다시 가속한다. 누르고 있는 동안은
`Curves.linear`(등속)로 두고 손을 뗀 마지막 칸에서만 감속하도록 바꾸니 그제서야 흐르듯
이어졌다. 여기에 걸을 때 좌우로 뒤뚱거리기, 착지 스쿼시, 알 반동을 붙였다.

**조작.** 십자키는 손 위치를 버튼에 맞춰야 해서 불편했다. 화면 아래 아무 데나 눌러 기울이는
**가상 조이스틱**을 넣었고, 십자키에 익숙한 경우를 위해 설정에서 고를 수 있게 했다.
십자키도 연속 이동 시스템에 새로 물려서 조이스틱과 동일하게 부드럽다.

**화풍은 시행착오가 있었다.** 코드로 그리던 타일을 전부 그림 타일로 교체했더니 오히려
"예전이 더 귀엽다"는 판단이 들었다. 이유를 뜯어보니 세 가지였다 — 파스텔 두 톤이 교차하는
체커보드가 사라졌고, 색 채도가 올라가 차가워졌고, 벽이 꽉 찬 덩어리가 되면서 둥근 느낌이
죽었다. 그래서 **하이브리드**로 정리했다:

- 지형(잔디·벽·얼음·균열)과 알 → 코드로 그리는 파스텔 화풍
- 오브젝트(둥지·굴·단추·문)와 로고 → 그림 파일 (배경을 투명하게 처리해 체커보드 위에 얹음)

타일 크기도 "화면에 꽉 차게"로 계산하다 보니 작은 판은 거대해지고 큰 판은 작아져 널뛰었다.
기준 44로 고정하고, 판이 화면보다 클 때만 줄어들게 바꿨다.

**소리.** 이동음을 직접 합성했는데 사인파로 주파수를 훑는 방식이라 오리 울음처럼 들렸다.
결국 삐약영어 앱에서 쓰던 실제 삐약 소리 파일로 교체했다. 합성으로 흉내 낼 수 없는 영역이었다.

## 이어서 작업하는 사람에게 (Codex 등)

이 앱은 **플레이 스토어에 출시**돼 있다. 이미 남의 폰에 깔려 있으니
"내 화면에서 잘 보이면 됨"으로 끝내면 안 된다. 아래는 실제로 밟아서
알게 된 것들이라, 모르고 건드리면 같은 데를 다시 밟는다.

### 손대기 전에 반드시 알아야 하는 것

**1. 빌드 전에 환경변수부터.** 이 기계는 사용자명이 한글이라 경로를
ASCII로 강제하지 않으면 `flutter test`가 "Connection closed before test
suite loaded"로 죽는다. 행(hang)처럼 보이지만 원인은 이것이다.
아래 [빌드](#빌드) 절의 네 줄을 매 셸 세션마다 먼저 실행한다.

**2. `lib/engine/`에 Flutter를 import하지 않는다.** 순수 Dart라서
솔버·검증 도구가 `dart run`으로 돌아간다. 여기 Flutter가 들어오면
`tool/*.dart`가 전부 못 돈다.

**3. 레벨 JSON을 손으로 고쳤으면 반드시 재검증한다.**
`optimal`(최소 수)은 솔버가 기록한 값이고 별 3개 판정의 기준이다.
판을 고치고 이 값을 안 고치면 **깰 수 없는 판이나 못 받는 별**이 생긴다.
```powershell
dart run tool/validate_levels.dart   # 전수 검증 + optimal 재기록
```

**4. 화면에 글자를 추가하면 13개 언어를 다 채운다.**
`lib/ui/strings_data.dart`의 13개 맵 전부에 키를 넣어야 한다.
하나라도 빠지면 `i18n_completeness_test.dart`가 잡고, 한국어를 그대로
두면 `no_korean_leak_test.dart`가 잡는다. **기본 언어는 영어다.**

**5. 이동 연출은 `SmoothPositioned`를 쓴다. `AnimatedPositioned`로 되돌리지 말 것.**
폰의 "애니메이션 끄기"(절전 모드 포함)가 켜지면 Flutter 기본값은
애니메이션 길이를 **5%로 줄여** 병아리가 칸에서 칸으로 순간이동한다.
`AnimationBehavior.preserve`로 막아 뒀다 (`lib/ui/widgets/board_view.dart`).

**6. 스크롤 목록에는 `scrollPadding(context)`을 쓴다.**
targetSdk 36이라 앱이 시스템 바 뒤까지 그린다(edge-to-edge 강제).
그냥 `EdgeInsets.all(16)`을 주면 **마지막 항목이 내비게이션 바에 가린다.**
헬퍼는 `lib/ui/theme.dart`에 있다.

**7. 소리 풀을 새로 만들면 쓰던 것을 반드시 `dispose`한다.**
안 하면 네이티브 오디오 플레이어가 쌓여 **앱이 통째로 죽는다**
(Dart 예외가 아니라 아무 메시지 없이 꺼진다). `SoundService._make` 참고.

**8. 판을 되돌리는 곳에서는 `_stopWalking()`을 부른다.**
걸음은 스스로 도는 고리다(`_step` → 타이머 → `_afterStep` → `_step`).
누르고 있던 방향이 남으면 **재시작해도 계속 걷고**, 걸음마다 소리가 끝없이 나서
앱이 꺼진다. 새로 판을 손대는 기능(재시작·되돌리기 등)을 만들면 이걸 부를 것.
`lib/ui/screens/game_screen.dart` 참고.

**9. 폰에 스토어판이 깔려 있으면 로컬 APK가 안 덮인다.**
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`이 나면 이것이다. **Play 앱 서명은
구글이 자기 키로 다시 서명**해서, 업로드 키로 만든 로컬 APK와 서명이 다르다.
지우고 새로 깔면 되지만 **진행 기록이 날아가니 먼저 사용자에게 물을 것.**
기록을 지키려면 콘솔에 올려 스토어에서 업데이트로 받아야 한다.

**10. 서명 키는 절대 건드리지 않는다.**
`android/upload.jks`와 `android/keystore.properties`는 `.gitignore`에 있다.
**왁뿌볼·끝말잇기와 같은 키**라, 새로 만들거나 잃어버리면 세 앱 전부
같은 패키지명으로 업데이트를 못 올린다. 백업은 `C:\workAndroid\_서명키_백업\`.

**11. 스토어 글에 광고·인앱결제·무료 이야기를 넣지 않는다.**
나중에 붙일 계획이라 지금 "없음"이라고 쓰면 그때 거짓말이 된다.
자세한 이유와, 실제로 붙일 때 같이 고쳐야 할 신고 항목은
`store/플레이스토어-작성내용.md` 9번에 있다.

## 빌드

이 개발 기계는 사용자명이 한글이라 **모든 경로를 ASCII로 강제**해야 한다. 매 셸 세션:

```powershell
$env:Path = "C:\flutter\bin;$env:Path"
$env:PUB_CACHE = "C:\flutter\.pub-cache"
$env:GRADLE_USER_HOME = "C:\workAndroid\gradle-user-ascii"
$env:TEMP = "C:\workAndroid\tmp-ascii"; $env:TMP = "C:\workAndroid\tmp-ascii"
```

- **TEMP/TMP 재지정은 필수다.** 기본 한글 temp 경로면 `flutter_tester`가 0xC0000409로
  즉사해서 `flutter test`가 "Connection closed before test suite loaded"로 실패한다.
  행(hang)처럼 보이지만 원인은 이것이다
- Android SDK는 `flutter config --android-sdk`, JDK는 `flutter config --jdk-dir`로
  ASCII 경로를 지정해 둔다

```powershell
flutter test                          # 전체 테스트
dart run tool/validate_levels.dart    # 레벨 전수 검증 + optimal 재기록
flutter build apk --release
adb install -r build\app\outputs\flutter-apk\app-release.apk
flutter build appbundle --release     # 스토어에 올릴 AAB
```

서명 키는 `android/upload.jks`, 비밀번호는 `android/keystore.properties`.
둘 다 `.gitignore`에 있다 — **저장소에 올라가면 안 된다.**
내 앱 전부가 같은 키를 쓴다 (왁뿌볼·끝말잇기와 동일). 이 키를 잃어버리면
같은 패키지명으로 업데이트를 영영 못 올린다.

## 레벨 추가·수정

### 손으로 만들기

`assets/levels/chapterN.json`에 항목을 추가한다:

```json
{"id": "c1s11", "chapter": 1, "title": "새 레벨", "rows": ["#####", "#@$o#", "#####"], "optimal": 0}
```

기호: `#`벽 `.`바닥 `@`병아리 `$`알 `o`둥지 `*`둥지 위 알 `+`둥지 위 병아리
`i`얼음 `c`금 간 바닥 `1~4`굴 쌍 `b`/`B`·`d`/`D` 단추/문

이후 **반드시** `dart run tool/validate_levels.dart`를 돌린다. 풀 수 없으면 실패하고,
`optimal`을 솔버 실측값으로 채워준다.

### 생성하기

챕터 6~20은 손으로 만들지 않고 생성했다. 시드가 챕터 번호로 고정돼 있어 재현된다:

```bash
dart run tool/gen_chapters.dart 11   # 한 챕터만 (난이도 조율용)
dart run tool/gen_chapters.dart      # 6~20 전부
```

난이도 밴드는 `tool/gen_chapters.dart`의 `specFor()`에 있다.

### 레벨 설계 시 함정 (실제로 밟은 것들)

- 알이 보드 가장자리 행/열에 있으면 그 축으로 밀 수 없어 데드락이 나기 쉽다
- 굴 출구 칸의 알은 "출구 옆 칸"에서만 밀 수 있다 — 병아리는 굴 칸에 서 있을 수 없다
  (들어가면 순간이동한다)
- 금 간 바닥 위의 알을 밀면 병아리가 따라가지 못한다. 밀기 경로의 균열은 둥지 직전에만 배치
- 문 너머로 알을 배달한 뒤 병아리가 돌아올 우회 통로가 있는지 확인 (문이 닫히면 갇힌다)

### 5차 — 300스테이지·다국어·출시 준비

**시작부터 알이 둥지에 놓여 있던 문제.** 판을 열었는데 알 몇 개가 이미 들어가 있는 게
자꾸 눈에 띄었다. 세어 보니 200개 중 **99개**가 그랬고 4막은 10판 전부였다.
원인은 생성 방식이었다. 완성 상태에서 거꾸로 흐트러뜨리는데, **전부 클리어된 판만
버리고 일부만 흐트러진 판은 통과**시키고 있었다. 알이 5개인 후반 챕터일수록
다 빼내기 어려워 심해진 것이다. 하나라도 둥지에 있으면 버리도록 고쳤다.

**"어려움"의 정의를 다시 잡았다.** 그동안 난이도 기준이 *최적 턴 수*였는데,
이건 3별 받기의 어려움이지 **깨는 것 자체의 어려움**이 아니다. 막 움직여도 결국 깨진다.
진짜 어려움은 **잘못 밀면 되돌릴 수 없게 되는 함정의 밀도**라고 보고 지표를 바꿨다.

여기서 두 번 헛발질했다.

1. 처음엔 "함정 15% + 턴 20+ + 밀기 12+ + 상태 6000+"를 동시에 요구했다. 후보가 **0개** 나왔다.
   분포를 재보니 각각 상위 3~15%라 동시 만족 확률이 사실상 0이었다.
   → 고정 문턱을 버리고 **후보를 많이 뽑아 난이도 점수 순으로 상위 5개**를 고르는 방식으로 바꿨다.
2. 더 근본적으로, **흐트러뜨리기가 알을 거의 안 옮기고 있었다.** 알 4개에 밀기 중앙값이 7,
   즉 알당 1.75칸이었다. 병아리가 무작위로 걷다 어쩌다 당기는 구조라 당길 기회가 드물었던 것이다.
   → **알을 하나 골라 끌어낼 자리까지 병아리를 보낸 뒤 연달아 당기는** 방식으로 교체했다.

그렇게 챕터마다 도전 5판을 붙여 **300스테이지**가 됐다. 4막 도전판은 27~67수다.

**생성 시간에서 크게 데었다.** 챕터 15까지는 한 챕터에 20분이었는데 16에서 **78분**으로 튀었다.
4막은 알이 5개라 솔버가 뒤질 경우의 수가 폭증하는데, 탐색 상한을 80만으로 잡고
후보를 220개나 뽑게 해둔 탓이다. 남은 4챕터에 5시간이 걸릴 판이라 중단하고
상한과 후보 수를 낮춰 다시 돌렸다. **비용을 실측 없이 낙관적으로 잡은 게 잘못**이었고,
코어가 16개인데 순차로 돌린 것도 놓친 부분이다.

**팅김의 원인.** 게임 중 앱이 죽는다는 걸 발견하고 뒤져 보니 힌트였다.
힌트 솔버에 상한이 **200만 상태**로 걸려 있었는데, 상태마다 보드와 문자열 키를 들고 있어
1GB 가까이 먹는다. 안드로이드가 프로세스를 죽이는 게 당연했다. 도전판이 깊게 탐색돼서
더 잘 터졌다. **12만으로 낮췄다.**

**힌트를 유한 자원으로.** 무제한이면 아무 판이나 힌트로 밀어버릴 수 있어 퍼즐이 성립하지 않는다.
새 스테이지를 깰 때마다 1개씩 들어와 대체로 한 판에 한 번 쓸 수 있다.
표시도 화살표에서 **번호(1~5)** 로 바꿨다 — 화살표만으로는 어느 칸 얘기인지 헷갈렸다.

**12개 언어.** `S` 클래스를 상수에서 조회 방식으로 바꾸고 언어별 표를 만들었다.
`const Text(S.x)` 자리를 전부 걷어내야 했다. 스테이지 300개의 제목까지 번역할 순 없어,
한국어는 손으로 붙인 이름을 쓰고 다른 언어는 챕터명과 번호로 만든다.

**앱 이름과 로고.** 한국어는 삐약푸쉬, 그 외에는 Peep Push로 나눴다(peep이 영어권 병아리 울음소리다).
타이틀 로고가 그림이라 언어를 바꿔도 제목이 안 바뀌었고, 그림 안에 병아리가 또 들어 있어
아래 병아리와 겹쳤다. **로고를 빼고 글자로 그렸다.**

**테스트를 안 돌린 대가.** 이번에 전체를 돌려 보니 두 개가 깨져 있었다.
알을 그림에서 코드 렌더링으로 되돌린 시점부터 실패하던 것과, 로고 그림이 생긴 뒤로
실패하던 것이다. 둘 다 화면에는 멀쩡히 보여서 몰랐다. 자산을 갈아끼울 때는
테스트도 같이 봐야 한다.

### 6차 — 그림 발주에서 배운 것

이번 차수는 대부분 그림 문제였다. 그런데 **같은 실수를 세 번 반복**하고서야
원인을 알았고, 그 원인이 그림이 아니라 **발주서**에 있었다.

**"배경이 잘린 느낌"의 정체.** 2막·4막 배경이 어딘가 허전하다는 지적을 받고
그림을 열어 봤지만 멀쩡했다. 잘린 데가 없었다. 수치를 재보고 알았다 —
그림 아래 20%의 색 표준편차가 **0.7·1.7**, 즉 사실상 단색이었다.
무지개도 달도 위쪽에 몰려 있었다.

문제는 **앱이 그림 위 35%를 크림색으로 지운다**는 것이다.
정성 들인 부분은 지워지고 빈 하늘만 크게 보였다. 배너 그림은 관습적으로
"위에 그림, 아래는 글자 자리"로 그려지는데, 우리 용도는 정반대였다.
**발주서에 앱 화면 도식을 그려 넣자 한 번에 해결됐다.**

**"파스텔로"는 지시가 아니다.** 3막 정원 배경이 혼자 튄다는 지적도 재보니
채도가 **0.69**, 나머지가 0.13~0.43인데 혼자 세 배였다. 발주할 때
"파스텔 톤으로"라고만 썼기 때문이다. **채도 0.25~0.35** 라고 숫자를 박으니
다음 납품은 0.31~0.34로 왔다.

**그래도 반만 찼다.** 색과 구도를 고쳤는데도 "아래가 반만 있다"는 말이 남았다.
계산해 보니 그림이 **1080×400, 가로가 세로의 2.7배**라 화면 폭에 맞추면
세로가 152dp뿐인데 채워야 할 곳은 276dp였다. 형태 자체가 용도에 안 맞았다.
**1080×1080 정사각형**으로 다시 받아 해결했다.

세 번을 헤맨 이유는 매번 "무엇을 그릴지"만 적고 **"어디에 어떻게 쓰이는지"를
안 적었기** 때문이다. 발주서 양식에 화면 도식과 수치 기준을 넣었다.

**정사각형이 되니 넘쳤다.** 그림이 세로로 길어지면서 가로가 넓거나 세로가 짧은
기기에서 화면 밖으로 넘쳤다. 테스트가 먼저 잡았다(RenderFlex 200px 초과).
남은 높이에 맞춰 줄이도록 고쳤다. 자산 비율을 바꿀 때는 레이아웃도 같이 봐야 한다.

**아이콘은 여덟 장을 받아 골랐다.** 처음엔 세 가지만 받아 골랐는데 쓰다 보니
아쉬웠다. 방향이 다른 **여덟 가지**를 한 번에 받으니 고르기 쉬웠다.
고른 것은 만세 하는 병아리와 둥지 속 알. 아이콘은 홈 화면에서 96픽셀로 보이므로
**줄여 놓고 판단**해야 한다 — 크게 보면 다 예쁘다.

### 7차 — 출시 점검

내보내기 전에 전부 한 번씩 눌러 보는 대신, **기계가 검사할 수 있는 것은 테스트로
바꿔 놓고** 사람이 봐야 하는 것만 남겼다. 그 과정에서 세 가지가 걸렸다.

**한국어가 코드에 박혀 있었다.** 문자열을 12개 언어로 옮겨 놓고도, 데일리 화면의
날짜(`8월 4일`)와 요일 머리글(`일 월 화…`)은 코드에 그대로 적혀 있었다.
일본 사용자가 달력을 열면 한글 요일이 나온다. 언어마다 날짜 적는 순서도 다르다
(`8월 4일` · `8/4` · `4/8` · `4.8.`). 이런 건 문자열 표를 훑어봐서는 안 보이고
**코드에서 한글을 찾아야** 나온다. 스티커 이름 24개도 같은 문제였는데,
이건 그림 위 툴팁일 뿐이라 번역 대신 툴팁을 없앴다.

**확인용 스위치가 배포판에 남아 있었다.** 설정의 "모든 챕터 열기 (확인용)"는
개발 중 편하려고 만든 것인데 그대로 나가고 있었다. 누구나 300스테이지를
건너뛸 수 있으니 챕터 구조가 무의미해진다. `kDebugMode`로 감쌌다.

**테스트가 옛 이름을 붙들고 있었다.** 앱 이름을 삐약푸시 → 삐약푸쉬로 바꿨는데
부팅 테스트가 옛 글자를 찾다 실패했다. 화면에 뜰 글자를 테스트에 그대로 적으면
이름이나 언어가 바뀔 때마다 깨진다. **앱이 쓰는 문자열을 참조**하도록 고쳤다.

검사 자체도 테스트로 남겼다(`i18n_completeness_test.dart`) —
번역 누락, 자리표시자(`{n}`) 유실, 버튼 문구 길이를 매번 확인한다.
언어를 새로 추가하거나 문자열을 고칠 때 자동으로 걸린다.

**"번역 다 됐다"와 "한글이 안 나온다"는 다른 말이었다.** 문자열 표가 12개 언어로
꽉 차 있어도 한 칸만 한국어로 남으면 그 화면에서 튀어나온다.
11개 언어의 모든 값 + 코드가 만들어 내는 값(스테이지 이름·날짜·요일)까지
한글이 있는지 훑는 테스트를 만들었다. 검사가 헛돌지 않도록
**한국어에서는 한글이 나오는지도 함께 확인**한다.

**번역이 길어서 화면이 깨지고 있었다.** 길이를 재보니 "다음 챕터"(4자)가
스페인어로 "Siguiente capítulo"(18자), "이전 챕터를 8판 깨면 열려요"(16자)가
53자였다. 실제로 렌더링해 보니 **클리어 팝업이 스페인어에서 349픽셀 넘쳤다.**
버튼 세 개를 `Row`에 늘어놨기 때문이다. 스페인어·프랑스어·독일어 사용자는
판을 깰 때마다 깨진 팝업을 봤을 것이다. 자리가 모자라면 아랫줄로 내리게 고쳤다.

한국어만 보면 절대 안 보이는 종류의 버그다. 길이 측정 도구
(`tool/check_text_length.py`)와 렌더링 검사(`long_text_overflow_test.dart`)를
남겨, 문구를 고칠 때마다 다시 볼 수 있게 했다.

**소리 하나 못 냈다고 앱이 안 켜질 수 있었다.** 시작 순서가
`타일 그림 준비 → 저장소 → 효과음 선로드 → 화면 띄우기`였는데, 앞의 셋이
예외를 던지면 화면을 못 띄운다. 오디오 초기화는 제조사·안드로이드 버전마다
동작이 달라 수천 기종에 뿌리면 어딘가에서 터진다. 한 대만 그래도 그 사용자는
**검은 화면**만 본다. 그림과 소리는 실패해도 게임은 돌아가야 하므로
(타일은 코드 렌더링, 소리는 무음으로 물러난다) 감싸서 계속 진행하게 했다.

**같이 나야 할 소리가 한 박자 밀렸다.** 알을 밀며 바닥이 무너질 때처럼
소리 두 개가 겹치는 경우, 뒤엣것이 앞엣것의 재생 요청이 끝나기를 기다리고
있었다(`await` 두 개를 이어 놓음). 동시에 띄우고 함께 기다리도록 바꿨다.
재생을 일부러 느리게 만든 뒤 두 소리의 시작 시각 차이를 재는 테스트로 확인한다.

**기기가 제각각이어도 버티는지 봤다.** 320dp 보급형부터 접는폰 펼침(673dp),
태블릿, 글씨 2배 확대, 가로 화면까지 게임 화면을 렌더링해 넘침이 없고
판이 알아볼 수 없을 만큼 작아지지 않는지 확인한다.

**챕터를 15판으로 늘렸는데 화면은 10판 기준이었다.** 챕터 카드의 별 만점이
`30`으로 박혀 있어, 한 챕터를 전부 3별로 깨면 **"45 / 30"**이 뜨고 진행바가
넘쳤다. 열심히 모은 사람만 보게 되는 화면이라 눈으로는 못 찾는다.
레벨 파일과 코드의 숫자를 직접 대조해서 잡았고,
`progression_consistency_test.dart`로 남겼다 — 판 수를 또 바꾸면
같이 고쳐야 할 곳(파일 수·id 규칙·별 만점·해금 조건)이 전부 걸린다.

**기준 언어를 한국어에서 영어로 바꿨다.** 우리가 안 가진 언어를 쓰는 기기에서
잠깐이라도 한국어가 스칠 여지를 없앴다. 이 변경이 테스트 6개를 깨뜨렸는데,
테스트가 `'클리어!'` 같은 **한국어 글자를 그대로 적어 두고** 있었기 때문이다.
앱이 쓰는 문자열을 참조하도록 고쳤다 — 이제 기본 언어를 바꾸든 문구를 다듬든
테스트는 살아 있다.

**번체 중국어를 더했다(13개 언어).** 간체만 있으면 대만·홍콩 사용자에게는
읽히긴 해도 남의 나라 글처럼 보인다. 글자만 바꾸지 않고 현지 어휘로 맞췄다
(设置→設定, 撤销→復原, 屏幕→螢幕). 안드로이드가 번체를 알려 주는 방식이
표기(`zh-Hant`)와 국가(`zh-TW`) 두 가지라 둘 다 본다.
"표만 복사하고 번역을 잊는" 실수를 막으려고, 번체 칸이 간체와 같으면
실패하는 테스트를 넣었다.

최종 상태: 정적 분석 경고 0, 테스트 203개 통과, 번역 누락 0건,
한글 유출 0건, 긴 번역 렌더링 이상 0건, 기기 다양성 이상 0건,
진행 규칙 정합성 이상 0건, 권한 0개.

### 8차 — 테스트가 못 잡는 것

앞 차수에서 "기계로 찾을 수 있는 건 다 찾았다"고 정리했는데,
바로 다음에 **직접 플레이하다 버그가 나왔다.** 테스트 203개가 하나도 못 잡은 것이다.

**두 칸이 한 번에 미끄러진다.** 빠르게 두 번 누르면 첫 칸이 안 보인 채
두 칸을 지나갔다. 원인은 코드가 틀려서가 아니었다 — 이동은 정확히 두 번
처리됐다. 한 걸음이 160ms 동안 움직이는데 **그 사이에 다음 입력이 들어오면
애니메이션의 목적지만 바뀌어**, 첫 칸이 그려지기 전에 두 칸 앞으로 목표가
옮겨진 것이다. 모델은 맞고 눈에만 틀리게 보이는 종류라, 상태를 검사하는
테스트로는 영원히 못 잡는다.

걸음이 끝날 때까지 다음 걸음을 미루되, 미룬 입력은 반드시 한 칸으로
이어지게 했다. 고치면서 구조도 정리했다 — 연속 이동을 주기 타이머로 따로
돌리고 있었는데 걸음 타이머와 **같은 간격이라 서로 어긋날 수 있는** 구조였다.
타이머 하나가 스스로 다음 걸음을 부르는 자체 순환으로 합쳤다.

여기서 한 번 더 배운 게 있다. 처음엔 `DateTime.now()`로 걸음 간격을 쟀는데
테스트가 통과하지 않았다. **위젯 테스트의 시계는 가짜라 `pump()`로 시간을
돌려도 `DateTime.now()`는 그대로**다. 타이머만 쓰도록 바꾸니 실제 동작도
같고 검증도 된다. **검증할 수 없는 방식으로 짜면 고쳤는지 알 수 없다.**

**테스트용 자유 이동.** 배포판에서 아무 스테이지나 확인하려면 전 챕터 해금이
필요한데, 스위치를 설정에 그냥 두면 누구나 300스테이지를 건너뛴다.
타이틀 제목을 일곱 번 두드리면 켜지도록 숨겼다(안드로이드 빌드번호 방식).

**이 차수의 교훈**은 앞 차수와 정반대다. 7차에서는 "눈으로 보면 못 찾는 것을
기계가 찾는다"였는데, 8차는 **"기계가 못 찾는 것을 손이 찾는다"**였다.
지금까지 사용자가 짚어 준 것들 — 효과음 밀림, 배경 크기, 기믹 누락, 두 칸
점프 — 이 전부 그 종류였고 전부 실제 결함이었다. 둘 다 필요하다.

최종 상태: 테스트 205개 통과, 정적 분석 경고 0.
남은 것은 **서명 키 생성과 AAB 빌드** — 사람이 해야 하는 일이다.

### 9차 — 13개 언어로 찍은 스크린샷

서명은 새로 만들지 않고 **왁뿌볼·끝말잇기와 같은 키**를 가져다 썼다.
앱마다 키를 따로 두면 언젠가 하나를 잃어버린다. 파일 이름만
`upload.jks`로 바꾸고 `keystore.properties`를 그대로 복사했다.
빌드한 AAB의 서명이 실제로 그 키인지는 `apksigner verify --print-certs`로
확인했다 — DN과 SHA-256 지문이 기존 앱과 같았다.

스토어 스크린샷은 언어마다 따로 올릴 수 있다. 13개 언어 × 7장 = 91장을
손으로 찍을 수는 없어서 `tool/shoot_all_langs.py`로 폰을 조종했다.
기기 언어는 adb로 못 바꾼다(루팅이 필요하다). 대신 **앱 안의 언어 선택**을
두드리게 했다 — 설정을 열고, 언어를 고르고, 타이틀·챕터·얼음판·힌트·
단추와 문·클리어 팝업·데일리를 차례로 찍는다.

**여기서 한 번 크게 틀렸다.** 언어 목록이 화면보다 길어서 아래쪽 언어는
목록을 밀어 올려야 닿는다. "밀어 올린 만큼 좌표에서 뺀다"고 짰는데,
목록이 **끝에 닿으면 요청한 만큼 안 밀린다.** 마지막 언어(인도네시아어)만
그만큼 어긋나서, `id` 폴더에 **베트남어 화면 7장**이 들어갔다.
파일은 멀쩡히 생기고 개수도 맞아서 로그로는 성공으로 보였다.

찍힌 그림을 직접 열어 보지 않았으면 그대로 스토어에 올라갔을 것이다.
고치는 방법은 계산을 정교하게 만드는 게 아니라 **계산을 안 하는 것**이었다.
끝까지 밀어붙인 다음 맨 아래 줄에서부터 세면, 얼마나 밀렸든 상관이 없다.
그리고 13개 언어를 하나씩 눈으로 확인했다 — 태국어 성조 부호가 제대로
얹히는지, 간체와 번체가 실제로 다른지, 베트남어 성조가 깨지지 않는지.
전부 정상이었다.

**교훈: 자동화의 성공 여부를 자동화의 로그로 판단하면 안 된다.**
스크립트는 "7장 찍었다"고 정직하게 보고했다. 틀린 건 장수가 아니라 내용이었다.

등록정보(앱 이름·간단한 설명·자세한 설명)도 13개 언어로 썼다.
`store/등록정보-13개국어.md`. 영어를 기본 언어로 지정한다 — 앱 자체도
영어가 기본이라 맞춰 놓는 편이 덜 헷갈린다.

**그리고 다 쓴 다음에 전부 고쳤다.** 처음엔 13개 언어 전부에 "광고 없음"을
넣었다. 지금 사실이니까. 그런데 나중에 광고와 인앱결제를 붙일 계획이다.
그 말은 **지금 참인 문장을 미래에 거짓말로 만들어 두는 것**이고, 그때 문구를
지운다고 해결되지 않는다 — 그걸 보고 받은 사람들이 그대로 남는다.

그래서 돈 이야기를 한 줄도 안 넣기로 했다. "무료"도 뺐다(인앱결제가 생기면
시비 대상이 된다). 딸려 있던 "인터넷을 쓰지 않는다"·"개인정보를 일절
수집하지 않는다"도 뺐다 — 광고 SDK는 인터넷 권한을 쓰고 광고 식별자를 읽는다.
남긴 건 **뭘 붙이든 계속 참인 말**뿐이다. 판이 몇 개고, 어떤 기믹이 있고,
매일 새 퍼즐이 나온다는 것. 무료라는 건 어차피 스토어가 가격 칸에 표시한다.

다만 데이터 보안 설문과 콘텐츠 등급은 **반대로** 뒀다. 그건 광고 문구가 아니라
**신고 사항**이라 올리는 빌드의 실제 모습대로 적어야 한다. 지금 빌드에는 광고도
결제도 없으니 "아니요"가 맞다. 대신 붙이는 날 같이 고쳐야 하는 것들을
`store/플레이스토어-작성내용.md` 9번에 목록으로 적어 뒀다 — 매니페스트 권한,
두 신고, 개인정보처리방침, 공개 페이지 문구. 순서도 적었다. **방침을 먼저
갱신하고 그다음에 광고가 든 빌드를 올린다.**

교훈 하나 더: 같은 문장을 두 저장소에 복사해 뒀더니 한쪽만 고치게 됐다.
등록정보 원본은 이제 게임 저장소 한 곳에만 두고, legal 쪽은 가리키기만 한다.

### 10차 — 비공개 테스트에서 나온 것들 (v1.0.1)

1.0.0을 비공개 테스트에 올리고 직접 해 보면서 나온 결함 넷을 고쳤다.
넷 다 **내 폰에서만 보이거나, 특정 기기 설정에서만 보이는** 종류였다.
테스트 205개를 통과한 채로 스토어에 올라간 빌드에 들어 있던 것들이다.

**앱이 그냥 꺼진다.** 방향키로 계속 걷다 보면 예고 없이 팅겼다. 폰이 연결돼
있지 않아 로그를 못 봤지만, "연속 이동 중"이라는 조건 하나로 코드를 뒤졌다.
8차에서 "소리가 죽으면 되살린다"고 넣어 둔 코드가 범인이었다 —
**쓰던 풀을 반납하지 않고 새로 만들기만 했다**(`AudioPool.dispose` 미호출).
풀 하나는 네이티브 오디오 플레이어를 여럿 쥐고 있어서, 되살릴 때마다
회수되지 않고 쌓인다. 게다가 되살리기에 상한이 없어 걸음마다 돌 수 있었다.
안드로이드의 동시 재생 한도를 넘기면 **Dart 예외가 아니라 네이티브에서
죽는다** — 그래서 아무 메시지도 없이 그냥 꺼진 것으로 보였다.
고치기 전 코드로 되돌려 재 보니 **100걸음에 풀 100개 생성 / 0개 반납**이었다.

여기서 배운 것: **버그를 고치려고 넣은 코드가 더 큰 버그가 될 수 있다.**
7차의 소리 끊김을 고치려던 되살리기가 8차를 지나 앱을 죽이고 있었다.
자원을 새로 잡는 코드를 넣을 땐 반납하는 짝을 같이 넣어야 한다.

**병아리가 딱딱 끊긴다.** 같은 앱인데 테스터 폰은 부드럽고 내 폰은 칸에서
칸으로 순간이동하듯 움직였다. 앱을 지웠다 깔아도 그대로였다.
처음엔 "플러터는 OS 애니메이션 설정과 무관하다"고 답했는데 **틀렸다.**
사용자가 "안 켜도 되게 할 수 없냐"고 되물어서 SDK 소스를 열어 봤더니,
`AnimationBehavior.normal`은 OS가 애니메이션을 끄면 **길이를 5%로 줄인다.**
160ms짜리 걸음이 8ms — 한 프레임 — 이 된다. 그리고 `AnimatedPositioned`는
그 동작을 끌 방법이 없다(내부에서 기본값으로 컨트롤러를 만든다).
같은 일을 하되 `AnimationBehavior.preserve`를 쓰는 `SmoothPositioned`로 갈았다.
절전 모드를 쓰는 **모든 실제 사용자**에게 일어났을 문제라, 테스트 중에 잡아 다행이다.

**굴이 미끄러진다.** 순간이동이어야 할 굴 통과가 보드를 가로질러 쭉
미끄러져 보였다. 애니메이션이 "이전 칸→새 칸"을 무조건 이어 주기 때문이다.
굴 이동이 일어난 프레임만 애니메이션 시간을 0으로 줬다.

**목록 마지막이 가린다.** 다른 앱(삐약수학)에서 하단 버튼이 내비게이션 바에
덮이는 걸 보고 이 앱도 같은 조건인지 전수 확인했다. targetSdk 35부터
앱이 시스템 바 뒤까지 그리는 게 기본이라(edge-to-edge 강제) 앱이 직접
피해야 하는데, 스크롤 목록 네 곳에 그 여백이 없었다.

**이 차수에서 테스트를 짜며 배운 것.** 처음 쓴 검사가 통과했는데,
알고 보니 찾는 대상이 없어 **아무것도 검사하지 않고 통과**한 것이었다.
그래서 두 가지를 규칙으로 넣었다 — 찾는 게 없으면 실패로 치고,
스크롤은 더 안 밀릴 때까지 되풀이한 뒤 끝에 닿았는지 확인한다.
(`ListView.builder`의 `maxScrollExtent`는 추정치라 한 번에 끝까지 안 간다.
그걸 모르고 잰 값으로 "22dp 겹침"을 "818dp"로 잘못 보고했다가 정정했다.)
그리고 네 건 모두 **고친 부분을 되돌려 실제로 실패하는 것까지 확인**했다.
통과하는 테스트는 통과할 뿐, 버그를 잡는다는 증거가 아니다.

조작 기본값도 조이스틱에서 방향키로 바꿨다. 저장된 설정이 없을 때만
적용돼 이미 쓰던 사람에게는 영향이 없다.

최종 상태: 테스트 218개 통과, 정적 분석 경고 0.
`1.0.1+2`로 올려 비공개 테스트에 배포했다. AAB 서명이 기존 키와 같은지,
versionCode가 올라갔는지 빌드 산출물에서 직접 확인했다.

### 11차 — 사용자의 짐작이 맞았다 (v1.0.2)

**"새로고침해도 이전 데이터를 물고 있는 것 같다."** 사용자가 이렇게 말했다.
한 판을 새로고침하고 움직이고를 반복하다 앱이 홈 화면으로 튕겼다는 것이다.
폰이 연결돼 있지 않아 로그는 못 봤지만, 그 짐작 한 줄이 정확했다.

걸음은 **스스로 도는 고리**다. `_step`이 타이머를 걸고, 타이머가 `_afterStep`을
부르고, 거기서 누르고 있는 방향이 남아 있으면 다시 `_step`을 부른다.
그런데 재시작·되돌리기가 그 방향을 지우지 않았다. 손 뗀 신호를 한 번만
놓치면(버튼이 다시 그려지거나 화면이 바뀔 때 생긴다) **판을 되돌려도
병아리가 계속 걷고, 걸음마다 소리가 끝없이 난다.** 소리가 끝없이 나면
네이티브 오디오 자원이 쌓여 앱이 통째로 꺼진다.

테스트로 재 보니 재시작 뒤에도 아무 입력 없이 다섯 칸을 더 걸었다.
사용자가 본 "이전 데이터를 물고 있다"가 화면에서는 그렇게 보였던 것이다.

같은 자리에서 하나 더 나왔다. **벽에 대고 누르고 있으면 160ms마다 계속
부딪히는 소리가 났다.** 스무 걸음을 재니 스물한 번 울렸다. 막힌 걸 알면서
계속 밀어붙일 이유가 없으니, 막히면 자동 반복을 멈추게 했다.
게임에서 벽에 붙어 누르는 건 흔한 일이라 이쪽이 더 자주 터졌을 것이다.

고친 것은 한 곳이다 — 판을 손대는 쪽에서 걷던 상태를 확실히 끊는 함수 하나.
재시작과 되돌리기가 그걸 부른다.

**힌트도 손봤다.** "누르면 바로 안 되고 생각하는 데 시간이 걸린다"는
지적이었는데, 실제로 별도 아이솔레이트에서 최대 12만 상태를 탐색한다.
그동안 화면이 아무 반응이 없으니 안 눌린 줄 알고 또 누르게 된다.
그리고 길을 못 찾으면 **조용히 아무 일도 일어나지 않아서** 고장 난 줄 안다.

세 가지로 바꿨다. 쓰기 전에 한 번 묻고(실수로 눌러 하나 날리지 않게),
푸는 동안 도는 표시를 띄우고, 이미 깰 수 없는 판이면 그렇다고 알린다.
못 찾았을 때 힌트를 깎지 않는 규칙은 원래 있었는데, 말을 안 해 줘서
그 배려가 전달되지 않고 있었다. **아무 일도 안 일어나는 것은
친절이 아니라 고장으로 읽힌다.**

문구는 13개 언어에 다 넣었다(`hintAsk`·`hintAskBody`·`hintUse`·
`hintNoPath`·`hintNoPathBody`).

**이 차수의 교훈**: 사용자가 원인을 짚어 주면 그 말부터 따라가 본다.
"이전 데이터를 물고 있다"는 기술 용어가 아니지만 정확히 그 일이 벌어지고
있었다. 폰 로그가 없어도 증상 조건("새로고침하고 움직이기를 반복")
하나만으로 코드에서 찾아낼 수 있었다.

최종 상태: 테스트 224개 통과, 정적 분석 경고 0.
`1.0.2+3`으로 올렸다. versionCode가 3으로 올라갔는지는 AAB 바이트가
헷갈려서 같은 소스로 APK를 만들어 `aapt`로 확인했다.

**실기기 설치에서 하나 배웠다.** S20 Ultra에 APK를 넣으려니
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`이 났다. 폰에 깔린 것은 스토어에서 받은
빌드인데, **Play 앱 서명은 구글이 자기 키로 다시 서명**하기 때문에
내가 업로드 키로 만든 APK와 서명이 다르다. 덮어쓰기가 안 된다.
지우고 새로 깔면 되지만 **진행 기록이 날아간다** — 그래서 물어보고 진행했다.

앞으로 스토어에 올라간 뒤에는 이 점을 기억할 것:

| 확인하려는 것 | 방법 |
|---|---|
| 코드 수정이 됐는지 빨리 보기 | 로컬 APK. 단, 스토어판을 지워야 하고 기록이 날아간다 |
| 실제 사용자와 같은 조건 | 콘솔에 올려 스토어에서 업데이트 받기. 기록 유지, 검토 시간 필요 |

설치 후 `dumpsys package`로 `versionCode=3 / versionName=1.0.2`를 확인하고
실행까지 봤다. 그 뒤 비공개 테스트에 1.0.2를 올렸다.

## 아트 교체

### 타일

`assets/images/tiles/`에 해당 파일명의 PNG가 있으면 그림을 쓰고, 없으면 코드로 그린다.
현재는 둥지만 그림이고 나머지 지형·기믹은 전부 코드 렌더링이다 —
따로 생성한 그림은 아무리 스타일을 맞춰도 미묘하게 겉돌았다.

| 도구 | 하는 일 |
|---|---|
| `tool/normalize_tiles.py` | 타일 배경색을 잔디 초록으로 통일 |
| `tool/transparent_tiles.py` | 오브젝트 타일의 배경을 투명하게 (체커보드 위에 얹기) |
| `tool/fill_tiles.py` | 그림 여백을 잘라내 캔버스를 꽉 채우게 (타일끼리 붙이기) |

### 배경

`assets/images/bg/bg_act1~4.png`, **1080×1080 정사각형**.
화면 아래에 깔리고 위 25%(`ActBackground.fadeStop`)가 크림색으로 녹는다.
**아래 75%에 알맹이를 두어야** 보인다. 그림을 바꿀 때는
`ActBackground.aspect`도 함께 맞춘다.

### 앱 아이콘

```bash
python tool/apply_icon.py 6
```

`PiyakAssets/icon2/icon2_<n>.png`(불투명)와 `icon2_<n>_fg.png`(투명)를 받아
런처 5종·적응형 앞층 5종·스토어 512를 한 번에 만든다.
적응형 아이콘은 `ic_launcher.xml`에서 inset을 주지 않는다 —
앞층 그림이 이미 안전영역 안에 있어서 이중으로 여백이 생긴다.

### 폰트

```bash
python tool/check_font_coverage.py
```

Jua는 한글 전용이라 13개 언어 중 10개의 글자가 없다.
`kJuaLanguages`(ko·en·id)만 Jua를 쓰고 나머지는 기기 폰트로 그린다.
문자열을 추가하면 이 도구로 다시 재 본다.
