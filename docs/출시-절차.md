# 플레이 스토어 출시 절차

순서대로 하면 된다. **①은 본인이 해야 하고**(비밀번호가 걸린다),
②③은 ①이 끝나면 이어서 진행할 수 있다.

등록정보(앱 이름·설명·데이터보안 답변 등)는
`C:\workAndroid\legal\peeppush\store-listing.md` 에 그대로 옮겨 쓸 수 있게 정리돼 있다.

## ① 서명 키 만들기 — 본인이 직접

앱은 서명이 있어야 스토어에 올라간다. 지금은 디버그 키로 서명돼 있어 **업로드가 거부된다.**

```powershell
cd C:\workAndroid
keytool -genkey -v -keystore peeppush.jks -keyalg RSA -keysize 2048 -validity 10000 -alias peeppush
```

물어보는 것들:

| 질문 | 답 |
|---|---|
| Enter keystore password | **직접 정한다. 반드시 기억/보관** |
| Re-enter new password | 같은 값 |
| 이름·조직·도시·국가 | 아무렇게나 적어도 된다 (스토어에 안 보인다). 국가는 `KR` |
| Is CN=... correct? | `y` |

> ### 잃어버리면 끝이다
> 이 키를 잃어버리면 **같은 앱을 두 번 다시 갱신할 수 없다.**
> 새 패키지명으로 새 앱을 올려야 하고 기존 사용자·리뷰는 전부 날아간다.
>
> - `peeppush.jks` 파일을 **깃 저장소가 아닌 곳**에 백업 (구글 드라이브, USB 등)
> - 비밀번호도 함께 적어 둔다
> - `.gitignore`에 이미 막아 뒀지만, 실수로 커밋하지 않도록 주의

키를 만들었으면 **비밀번호를 알려 주지 말고** "만들었다"고만 알려 주면 된다.
연결 작업은 대신 해 줄 수 있다 — 비밀번호는 `android/key.properties`에
본인이 적어 넣으면 된다(이 파일은 깃에 안 올라간다).

## ② AAB 만들기 — 키가 생긴 뒤

스토어는 APK를 안 받는다. **AAB(App Bundle)** 를 받는다.

```powershell
flutter build appbundle --release
```

결과물: `build\app\outputs\bundle\release\app-release.aab`

버전은 `pubspec.yaml`의 `version: 1.0.0+1`에서 온다.
갱신할 때마다 뒤 숫자(`+1`)를 반드시 올려야 한다 — 같은 번호는 업로드가 거부된다.

## ③ 그래픽 자산 — 직접 찍고 만들어야 함

| 자산 | 규격 | 상태 |
|---|---|---|
| 앱 아이콘 | 512 × 512 PNG | **준비됨** `store/icon_512.png` |
| 그래픽 이미지 | 1024 × 500 | 아직 |
| 휴대전화 스크린샷 | 2~8장, 9:16 | 아직 |

스크린샷은 폰에서 직접 찍는다:

```powershell
adb exec-out screencap -p > shot1.png
```

찍으면 좋은 순서 (게임의 특징이 드러나는 차례):

1. 타이틀 — 병아리와 메뉴
2. 얼음 판 — 알이 미끄러지는 장면
3. 단추와 문이 열린 장면
4. 힌트를 켠 화면 — 번호 1~5가 보이는 판
5. 클리어 팝업 — 별 3개
6. 챕터 목록 — 20챕터가 쭉 보이는 화면

> 개발자 모드(타이틀 제목 일곱 번 두드리기 → 설정 → 모든 챕터 열기)를 켜면
> 후반 챕터 화면도 바로 찍을 수 있다.
> **스크린샷을 다 찍은 뒤에는 개발자 모드를 꺼 두는 게 좋다.**

그래픽 이미지(1024×500)는 스토어 목록 맨 위에 걸리는 배너다.
게임 배경 그림에 병아리와 제목을 얹으면 된다 — 필요하면 만들어 줄 수 있다.

## ④ 플레이 콘솔에서 할 일

1. **개발자 계정 등록** (최초 1회, 미화 25달러)
2. 앱 만들기 → 이름·기본 언어 설정
3. `store-listing.md`의 값들을 옮겨 넣기
   - 앱 이름 (한국어/영어)
   - 간단한 설명, 자세한 설명
   - 개인정보처리방침 URL
4. **데이터 보안 설문** — `store-listing.md` 3번 표 그대로.
   앱이 실제로 하는 일과 다르게 적으면 정지 사유다
5. **콘텐츠 등급 설문** — 전부 "없음" → 전체이용가
6. **AAB 업로드**
7. **내부 테스트 트랙에 먼저 올린다.** 본인 계정으로 설치해 실제로 돌아가는지
   확인한 뒤 정식 출시로 넘긴다. 바로 프로덕션에 올리면 문제가 있어도 못 되돌린다
