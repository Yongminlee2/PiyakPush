# 삐약푸시 v1.1 — 실기기 피드백 반영 설계

- 날짜: 2026-08-02
- 상태: 승인됨
- 기반: `2026-08-02-piyakpush-design.md` (v1). 이 문서는 v1 실기기 플레이 후 나온 5건의 피드백만 다룬다.

## 배경

v1을 S20에 설치해 플레이한 뒤 받은 피드백 5건:

1. 이동할 때 삐약삐약 소리가 났으면 좋겠다
2. 방향키가 가운데 몰려 있어 조작이 불편하다
3. 챕터 10번째 스테이지를 깨면 다음 판으로 갈 수 없다
4. 전체적인 디자인을 손봤으면 좋겠다
5. 이동이 딱딱 끊기는 느낌이다 — 부드럽게 움직였으면 좋겠다

3번은 기능 결손(버그), 나머지는 게임 필(feel)과 외형 개선이다.

## 1. 삐약 울음소리

현재 `move.wav`는 660Hz 사각파 60ms 블립 — 병아리 소리가 아니다.

- `tool/gen_sfx.py`에 2음절 처프 합성을 추가한다: 상승 스윕(900→1400Hz) 후 하강 스윕(1400→700Hz), 총 110ms, 사인파 기반에 부드러운 어택.
- 음높이가 다른 3종(`chirp1`, `chirp2`, `chirp3`)을 생성해 `SoundService`가 **호출마다 순환** 재생한다. 같은 소리 반복으로 인한 기계적 느낌을 없앤다.
- 기존 `move.wav`는 제거하고 `Sfx.move` 재생 요청이 순환 처프로 매핑되게 한다. `SoundService`가 순환 인덱스를 소유하며, 인덱스는 재생할 때만 증가한다(음소거 시 증가하지 않음).
- 알 미는 소리(`push`, 220Hz 저음)는 그대로 둔다 — 걷기와 밀기가 청각적으로 구분돼야 한다.

## 2. 방향키 확대 (A안)

- 버튼 60→76px, 아이콘 40→48px, 십자 중앙 간격 60→76px(버튼 한 칸 크기).
- 터치 판정은 시각 크기보다 넉넉하게: 버튼 컨테이너에 6px 투명 여백을 두고 `Listener`가 그 영역까지 받는다.
- 꾹 누르기 연속 이동은 유지하되 간격은 5절에서 재조정한다.

## 3. 챕터 마지막 스테이지 → 다음 챕터 (버그 수정)

현재 `StageScreen._gameRoute`는 마지막 스테이지에서 `onNext`를 `Navigator.pop`으로 연결한다 — "다음"을 눌러도 목록으로 되돌아갈 뿐 다음 챕터로 가는 경로가 없다.

**"다음에 무엇을 할지" 판단을 화면에서 분리해 순수 함수로 만든다.** 화면 없이 테스트 가능해야 같은 결손이 재발하지 않는다.

```dart
sealed class NextStep {}
class NextInChapter extends NextStep { final int index; }      // 같은 챕터 다음 스테이지
class NextChapter extends NextStep { final int chapter; }       // 다음 챕터 첫 스테이지
class ChapterLocked extends NextStep { final int chapter; final int starsNeeded; }
class AllChaptersCleared extends NextStep {}

NextStep resolveNextStep({
  required int chapter,
  required int index,
  required int levelCount,
  required int currentChapterStars, // 현재 챕터에서 모은 별 (다음 챕터 해금 판정용)
  required int chapterCount,        // 5
});
```

판정 규칙:
- `index + 1 < levelCount` → `NextInChapter(index + 1)`
- 마지막 스테이지이고 `chapter < chapterCount`이며 현재 챕터 별 ≥ 12 → `NextChapter(chapter + 1)`
- 마지막 스테이지이고 `chapter < chapterCount`인데 별 < 12 → `ChapterLocked(chapter + 1, 12 - 현재별)`
- 마지막 챕터의 마지막 스테이지 → `AllChaptersCleared`

화면 동작:
- `NextInChapter` — 지금처럼 `pushReplacement`로 이어서 플레이
- `NextChapter` — 해당 챕터의 `StageScreen`으로 교체 진입 후 1스테이지 시작. 클리어 팝업 버튼 문구는 "다음 챕터"
- `ChapterLocked` — 팝업에 "별 N개만 더 모으면 다음 챕터가 열려요" 문구를 띄우고 버튼은 "목록"만 남긴다
- `AllChaptersCleared` — "모든 챕터 클리어!" 문구와 함께 타이틀로 돌아가는 버튼

## 4. 디자인 개선

### 4.1 게임 화면 여백·배치

보드가 넓은 크림 배경 위에 떠 있어 화면이 비어 보인다.

- 보드를 **패널로 감싼다**: 크림보다 한 톤 진한 배경(`#F2E7C9` 계열) + 진갈색 외곽선 + 둥근 모서리, 안쪽 패딩 10px.
- 타일 크기 상한 72→96px로 올려 남는 공간을 보드가 차지하게 한다.
- 세로 배치를 HUD(고정) → 보드(남는 공간 차지, 중앙 정렬) → 방향키(하단 고정) 순으로 정리하고 각 사이 간격을 명시한다.
- HUD를 카드형(흰 배경 + 외곽선)으로 감싸 상단이 허전하지 않게 한다.

### 4.2 타이틀·메뉴 화면

- 타이틀 로고를 카드 패널 위에 얹고 병아리를 함께 배치.
- 별 진행도를 "14 / 150" 텍스트 대신 **진행바 + 숫자**로.
- 시작 버튼만 노란색 강조, 나머지는 흰색 유지(주 동작 하나만 강조).
- 챕터 카드에 **기믹별 테마색** 좌측 스트립과 진행바 추가: 1 풀밭 초록, 2 얼음길 하늘, 3 비밀굴 보라, 4 단추와문 분홍, 5 금간바닥 갈색.

### 4.3 보드 그래픽 디테일

`BoardPainter`에 추가:
- 풀밭 타일에 작은 잔디 무늬(v자 2개)를 타일 좌표 기반으로 결정적 배치 — 매 프레임 흔들리면 안 되므로 난수 대신 좌표 해시를 쓴다.
- 둥지에 지푸라기 결 선 2~3개.
- 벽 타일 아래쪽에 얇은 그림자 띠로 입체감.
- 알에 좌상단 광택 하이라이트(작은 흰 타원).

### 4.4 클리어 연출 + 별 표시 버그

실기기 스크린샷에서 클리어 팝업의 별이 하나도 보이지 않았다(이동 9 / 최적 7 → 별 2개여야 정상). 원인을 규명해 고친다(추정: `ScaleTransition` 컨트롤러가 전진하지 않아 scale 0으로 남음 — 실제 원인은 구현 시 확인).

- 미획득 별도 **항상 보이는 회색 실루엣**으로 렌더링한다(현재는 컨트롤러 미전진으로 함께 사라짐).
- 획득 별은 순차 등장 유지 + 꽃가루 파티클(커스텀 페인터, 외부 의존성 없음) 추가.
- 위젯 테스트로 별 개수를 검증한다: 별 3/2/1 각각에 대해 노란 별 아이콘 개수가 맞는지.

## 5. 이동 부드럽게

원인 세 가지가 겹쳐 있다.

| 원인 | 현재 | 변경 |
|---|---|---|
| 연속 이동 시 빈틈 | 이동 120ms / 반복 간격 160ms → 매 칸 40ms 정지 | 이동 160ms / 반복 170ms로 거의 맞물리게 |
| 칸마다 급브레이크 | `Curves.easeOut` | `Curves.easeInOut` |
| 점프 엇박 | hop 220ms (이동 120ms보다 김) | hop 160ms로 이동과 동기 |

추가: **막힌 입력에 무반응**인 것도 뻣뻣함의 원인이다. 벽·알에 막혀 이동이 실패하면 병아리가 그 방향으로 살짝 밀렸다 돌아오는 반응(약 12% 셀 크기, 140ms)을 준다. 실패한 이동은 이동수에 포함되지 않으며 보드 상태도 바뀌지 않는다 — 순전히 시각 피드백이다.

`GameController.move`는 이미 성공 여부를 bool로 돌려주므로, 화면이 실패 시 `BoardView`에 "막힌 방향"을 전달해 흔들기만 하면 된다.

## 테스트 전략

- `resolveNextStep` 단위 테스트: 챕터 중간, 챕터 마지막+해금, 챕터 마지막+잠김(부족 별 수 확인), 마지막 챕터 마지막.
- `ClearPopup` 위젯 테스트: 별 3/2/1에 대해 노란 별 개수 검증(4.4의 회귀 방지).
- `SoundService` 단위 테스트: 처프 3종 순환(연속 호출 시 asset 경로가 chirp1→2→3→1), 음소거 시 인덱스 미증가.
- 기존 154개 테스트는 전부 통과해야 한다. 애니메이션 상수(ms)는 테스트하지 않는다 — 시각 튜닝 값이라 테스트가 변경을 방해한다.
- 실기기 설치 후 육안 확인: 방향키 조작감, 이동 연속성, 챕터 전환, 클리어 별.
