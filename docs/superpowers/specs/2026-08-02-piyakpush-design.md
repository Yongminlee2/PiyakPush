# 삐약푸시 (PiyakPush) 설계 문서

- 날짜: 2026-08-02
- 상태: 승인됨 (사용자가 방향 승인 후 자율 진행 위임)
- 대상 플랫폼: Android 우선 출시, iOS 호환 유지 (스토어 제출은 맥 확보 후)

## 1. 개요

푸쉬푸쉬(소코반) 규칙 기반의 모바일 퍼즐 게임. 병아리가 **알을 밀어 둥지에 넣는** 것이 목표다.
Flutter로 개발하며, 기존 삐약 시리즈의 병아리 캐릭터·스티커 에셋(`C:\workAndroid\PiyakAssets`)을 재활용해
아기자기하고 귀여운 톤을 유지한다. v1은 광고·결제 없는 완전 무료.

- 본편 50 스테이지 (5챕터 × 10) + 데일리 보너스 퍼즐 1개/일
- 프로젝트 위치: `C:\workAndroid\PiyakPush` (독립 git 저장소)
- 앱 표시명: 삐약푸시 (영문 PiyakPush)

## 2. 핵심 규칙

- 격자 보드. 병아리는 상하좌우 4방향으로 한 칸씩 이동한다.
- 병아리가 알 방향으로 이동하면 알을 한 칸 민다. 알 두 개 연속, 알 뒤가 벽/문(닫힘)/구멍이면 밀 수 없다.
- 알을 당기는 조작은 없다.
- 모든 알이 둥지 칸 위에 오면 스테이지 클리어.
- 알이 둥지에 올라가면 시각적으로 표시(알이 살짝 자리 잡는 연출)되지만 계속 밀 수 있다.
- 이동수 카운트: 병아리의 한 칸 이동 = 1수 (밀기 포함). 별점 기준에 사용.
- 되돌리기(undo)는 무제한. 재시작 즉시 가능. 클리어 전 어떤 상태에서도 사용 가능.

## 3. 기믹 (챕터별 도입)

| 챕터 | 스테이지 | 기믹 | 규칙 |
|---|---|---|---|
| 1 | 1–10 | 기본 | 벽·알·둥지만. 1–3은 튜토리얼(말풍선 안내). |
| 2 | 11–20 | 얼음 | **알만** 미끄러진다. 얼음 위로 밀린 알은 얼음이 이어지는 동안 계속 미끄러지고, 얼음이 아닌 칸에 들어서거나 장애물(벽·알·닫힌 문)에 막히면 멈춘다. 병아리는 얼음 위를 평범하게 걷는다. |
| 3 | 21–30 | 텔레포트 굴 | 굴은 쌍으로 존재. 알이나 병아리가 굴 칸에 들어가면 짝 굴로 즉시 이동. 짝 굴 출구가 막혀 있으면(알이 점유) 들어갈 수 없다(이동 불가로 처리). |
| 4 | 31–40 | 버튼·문 | 버튼 위에 알 또는 병아리가 있는 동안 연결된 문이 열린다. 문이 닫힐 때 그 칸에 알·병아리가 있으면 문은 열린 상태를 유지한다(끼임 방지). 버튼–문 연결은 같은 색상으로 표시. |
| 5 | 41–50 | 금 간 바닥 + 종합 | 금 간 바닥은 병아리가 밟고 **떠나는 순간** 구멍이 된다(알이 지나가도 동일). 구멍에는 병아리도 알도 들어갈 수 없다. 챕터 5는 앞선 기믹들을 조합한 종합 스테이지. |

기믹 간 상호작용 우선순위: 이동 판정 → 텔레포트 → 얼음 미끄러짐(미끄러지는 중에도 굴·버튼 판정 적용) → 바닥 붕괴 → 문 상태 갱신 순으로 처리한다. 미끄러지는 알이 굴에 들어가면 짝 굴에서 나온 뒤, 나온 칸이 얼음이면 같은 방향으로 계속 미끄러진다.

## 4. 별점·데드락

- 별 3개: 솔버가 계산한 최적 이동수 이하로 클리어
- 별 2개: 최적 이동수의 1.5배 이하 (올림)
- 별 1개: 클리어
- 간단 데드락 감지: 둥지가 아닌 칸에서 알이 모서리(직교 두 방향이 벽)에 갇히면 병아리가 슬픈 포즈 + "되돌리기 어때?" 말풍선. 강제 재시작은 없음.

## 5. 메타 시스템

### 스티커 수집·꾸미기
- 별 누적 개수로 스티커 해금 (총 150개 별 → 스티커 24종 목표, 초기엔 기존 12종 + 신규 12종).
- 스티커북 화면: 해금/미해금 실루엣 표시.
- 꾸미기 보드: 해금한 스티커를 자유 배치(드래그)하는 한 장짜리 보드. 배치 상태 로컬 저장.

### 병아리 감정 연출 (기존 포즈 11종 활용)
- 대기 10초 → think, 30초 → sleep. 입력 시 idle 복귀.
- 클리어 → cheer + clap 교차. 별 3개면 cheerup 추가.
- 데드락 감지 → sad. 튜토리얼 안내 → speak.

### 데일리 퍼즐
- 날짜를 시드로 한 역방향 생성(완성 상태에서 알을 거꾸로 당기며 N수 역산 → 항상 풀이 가능 보장) 후 솔버로 난이도(최적 수) 확인, 범위 밖이면 재생성.
- 클리어 시 달력에 도장. 연속 출석 표시. 생성 실패 시(시도 상한 초과) 내장 프리셋 20개에서 날짜 해시로 선택.

## 6. 화면 구성

1. **타이틀**: 로고 + 병아리, [시작] [데일리] [스티커북] [설정]
2. **챕터 선택**: 5챕터 카드(잠금은 이전 챕터 별 12개 이상으로 해제)
3. **스테이지 선택**: 10개 그리드, 별 표시
4. **게임 화면**: 상단(스테이지 번호·이동수/최적수·재시작·되돌리기·힌트·설정), 중앙 보드(화면 크기에 맞춰 자동 스케일), 조작은 스와이프(한 칸 이동). 설정에서 화면 하단 D-패드 켜기 가능.
5. **클리어 팝업**: 별 연출 → 이동수/최적수 → [다음] [다시] [목록]
6. **스티커북 / 꾸미기 보드 / 데일리 달력 / 설정**(사운드 토글, D-패드 토글, 진행 초기화)

- 힌트: 현재 상태에서 솔버 실행 → 다음 5수를 보드 위 화살표로 표시. 무료, 횟수 제한 없음(v1).

## 7. 기술 아키텍처

- Flutter stable + 순수 위젯 (Flame 미사용). 상태 관리 `provider`(ChangeNotifier), 저장 `shared_preferences`, 사운드 `audioplayers`. 모든 의존성 iOS 호환 확인 후 채택.
- 폴더 구조:
  - `lib/engine/` — 순수 Dart, Flutter 의존 금지. 보드 상태, 이동·기믹 판정, 데드락, 솔버(BFS+데드락 가지치기). 단위 테스트 집중 대상.
  - `lib/models/` — 레벨 정의, 진행 저장 모델
  - `lib/ui/` — 화면·위젯·애니메이션
  - `lib/services/` — 저장, 사운드, 데일리 생성
  - `assets/levels/` — 레벨 JSON, `assets/images/`, `assets/audio/`
  - `tool/` — 레벨 검증 CLI(전 레벨 솔버 실행 → 풀이 불가/최적수 산출, `dart run tool/validate_levels.dart`)
- 레벨 포맷: ASCII 격자 JSON. `#`벽 `.`바닥 `@`병아리 `$`알 `*`둥지 위 알 `o`둥지 `+`둥지 위 병아리 `i`얼음 `c`금 간 바닥. 굴 쌍은 숫자 짝(`1`↔`2`, `3`↔`4`)으로 최대 2쌍. 버튼은 소문자(`b`,`d`), 대응 문은 같은 글자의 대문자(`B`,`D`)로 최대 2쌍. 메타(제목, 챕터)는 JSON 필드, 최적수는 검증 툴이 기록.
- 애니메이션: 이동 120ms `AnimatedPositioned`, 미끄러짐은 칸당 60ms 연속, 클리어 별은 `ScaleTransition`+파티클(커스텀 페인터).
- 이미지: 병아리·스티커는 PiyakAssets 재활용. 신규 필요: 알, 둥지, 타일(풀밭·얼음·굴·버튼·문·금 간 바닥·벽), 로고. 생성형으로 제작하되 기존 스타일(진갈색 외곽선·볼터치·파스텔)을 맞춘다.
- 사운드: 이동·밀기·미끄럼·클리어·해금 등 짧은 SFX. CC0 소스 또는 합성으로 확보.
- 빌드 환경: Flutter SDK는 ASCII 경로(`C:\flutter`)에 설치. Android SDK는 기존 `C:\workAndroid\android-sdk-ascii`, Gradle 홈은 `gradle-user-ascii` 재활용(한글 사용자명 경로 함정 회피). iOS 빌드는 코드 호환만 유지.

## 8. 스테이지 제작 원칙

- 보드 크기 6×6 ~ 10×10, 알 1~5개.
- 각 챕터 1~2번째 스테이지는 신규 기믹 단독 학습용(작고 쉬움), 이후 난이도 상승, 10번째는 챕터 보스급.
- 전 레벨은 커밋 전 `tool/validate_levels.dart` 통과 필수(풀이 가능 + 최적수 기록). 최적수 20수 미만이 전체의 70% 이상(모바일 호흡).

## 9. 테스트 전략

- `lib/engine` 단위 테스트: 기본 밀기, 벽·이중 알 차단, 얼음 미끄러짐(연쇄·굴 통과·문 차단), 텔레포트(점유 차단), 버튼·문(열림·유지), 바닥 붕괴, 데드락 감지, 솔버 정답성(기지 레벨 최적수 일치).
- 레벨 검증 CLI를 테스트에 포함(50레벨 + 데일리 프리셋 전부 풀이 가능).
- 위젯 테스트: 게임 화면 스와이프 → 상태 변화, 클리어 팝업 표시 스모크.
- 수동 테스트: 실기기(S20 Ultra, adb 연결) 설치 확인.

## 10. 에러 처리

- 저장 로드 실패 → 기본 진행값으로 시작, 스낵바 안내(덮어쓰기는 첫 저장 시점).
- 레벨 JSON 파싱 실패 → 해당 스테이지 잠금 표시 + 다음 스테이지 진입 허용(출시 전 검증 CLI로 원천 차단).
- 데일리 생성 실패 → 프리셋 폴백(5절 참조).
